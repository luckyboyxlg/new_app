def run():

二、反调试

1、frida的反调试

之前做app，有frida的反调试---》打印所有so文件---》删除检测frida的so文件

有些app，在运行的时候，检测frida的相关特征，检测到后就直接退出app----》不允许使用frida调 Frida的Hook

  • 正常去运行APP，无额外的其他特征
  • 正常去运行APP + 运行frida进行Hook【在手机上会生成一个文件】
  • 有些app内部监测是否有这个文件，如果有这个文件，那么就让app强制停止
  • 酒仙网app---》就是检测是否有frida运行的特征：文件

2、frida的增强版

  • frida的增强版---》把frida名字改掉---》运行的时候--》没有frida的特征 strongR-frida-android

它不针对所有app，只针对于 检测frida特征的app有效

  • 网址 https://github.com/hzzheyang/strongR-frida-android/releases

  • 说明

跟随 FRIDA 上游自动修补程序，并为 Android 构建反检测版本的 frida-server

strongR-frida-android 它的本质就是frida-server，只是改了名字

只要frida-server发一个版本，它一定会跟一个版本

  • 电脑上配置

hluda-server-16.2.1-android-arm64

3、配置步骤

  • 下载 跟python版本对应的 版本

  • 解压：把解压后的文件推送到手机上

adb /data/local/tmp adb push hluda /data/local/tmp/

  • 加执行权限

chomd 755 hluda

  • 查看权限

ls -al

  • 运行它即可---》以后就把这东西当 frida-server用即可

  • 以后可以不使用frida-server了，以后就用hluda 当frida-server用即可

4、下载与使用

此时我们可以尝试使用strongR-frida-android来绕过监测。

注意：酒仙网app就可以用它来绕过，但不一定适用所有其他app

三、脱壳

1、加壳原理

  • app

酒仙app，拖到jadx中，发现加壳了--》反编译不了

  • 安卓开发：

java代码+sdk+JNI代码 ----》apk(java代码写的：dex，JNI代码：so文件 资源文件 xml)

  • app加壳：

java代码+sdk+JNI代码--》使用第三方加壳工具---》把dex隐藏到 so文件--》dex很小，so很大

  • app运行时：未加壳app

把dex加载到内存中，执行了

  • app运行时：加壳app

先加载dex--》so文件加载进来---》dex都在so中--》逆操作--》从so中解出dex--》在内存中--》执行逻辑

2、脱壳方案（没有一种脱壳方案适用所有app）

  • 手动脱壳（难度大）：

通过动态调试，跟踪计算Dex源文件的内存偏移地址，从内存中Dump出Dex文件 难度大，寄存器，汇编，反调试，反读写

  • 工具脱壳：

HOOK技术/内存特征寻找 简单易操作 基于xposed 脱壳工具： Fdex2：Hook ClassLoader loadClass方法 通用脱壳 dumpDex：https://github.com/WrBug/dumpDex 基于frida的脱壳工具（咱们学习）： frida-dexdump：https://github.com/hluwa/FRIDA-DEXDump

      自己定制脱壳机--》aosp刷机后--》自己定制脱壳机
      armPro收费脱壳（花钱）

3、安装与使用

pip install frida-dexdump

想要使用frida-dexdump来进行脱壳，必须做如下两个步骤：

  • 手机端，启动frida-server

  • 电脑端

  • 端口转发

  • 执行脱壳命令

    python frida-dexdump -U -f 包名称

脱壳后，会生成相应的dex文件，例如：

frida-dexdump -U -f com.jiuxianapk.ui

4、脱壳步骤

  1. 安装模块[电脑端]： pip install frida-dexdump

  2. 手机端启动frida-server，端口转发

  3. 执行脱壳命令即可

frida-dexdump -U -f 包名称

frida-dexdump -U -f com.jiuxianapk.ui # 普通脱壳 frida-dexdump -U -d -f com.jiuxianapk.ui # 深度脱壳

  1. 使用jadx打开下载后的dex即可

  2. 有时候一次性把dex拖进去会报错

  3. 某个dex可能不是这个app或这个dex有问题

  4. 一个个的把dex拖入，哪个报错，就把哪个删除

  5. 每个dex都可以反编译成一部分java，但是由于下载的dex，某个可能有问题导致整个项目都反编译不了，找出那个有错的dex把它删除即可

  6. 原理

只要app运行了---》app就加载到内存中了---》在内存中 原来在so中dex，已经解出来在内存中了--》通过frida-dexdump--》可以去内存中搜索所有dex并下载到本地---》本地会生成很多dex，这些dex就是脱壳后的文件
