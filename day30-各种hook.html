7、hook中Java.perform

Java.perform 是 Frida 提供的一个 API，主要用于在 Android 应用中执行 Java 代码的 hook 操作。它确保了所有传入的 JavaScript 函数都在一个安全的环境中运行，并且该环境允许与 Java 类和对象进行交互。这个函数的主要作用是：

  1. 确保同步性：Java.perform 确保所提供的函数在一个合适的时机被调用，即当 JVM（Java 虚拟机）已经准备好处理来自 JavaScript 的请求时。这对于避免在 JVM 尚未初始化或处于不可预测状态时尝试操作 Java 对象是非常重要的。
  2. 提供上下文：它为传递给它的函数创建了一个适当的 Java 上下文，使得你可以在其中安全地使用 Java.use, Java.choose, Java.enumerateLoadedClasses 等其他 Frida-Java API 来 hook 或操纵 Java 类和方法。
  3. 保护作用域：Java.perform 内部的代码块是线程安全的，它保证了在多线程环境下对 Java 类和对象的操作不会引发冲突或不一致的状态。
使用场景

当你想要 hook 或修改 Android 应用中的 Java 方法时，你应该将你的操作包裹在 Java.perform 中。例如，如果你要 hook 一个特定的 Java 方法，你可以这样做：

javascript深色版本

Java.perform(function () {
    // 定义你想 hook 的类和方法
    var MainActivity = Java.use("com.example.MainActivity");

    // Hook 其中一个方法
    MainActivity.someMethod.implementation = function (arg) {
        console.log("someMethod was called with argument: " + arg);

        // 调用原始方法并返回结果（如果需要的话）
        return this.someMethod(arg); // 如果 you want to call the original method
    };
});

在这个例子中，Java.perform 确保了我们对 MainActivity 类的 someMethod 方法的 hook 操作是在一个正确的、线程安全的环境中进行的。

注意事项
  • 不要在 Java.perform 外部直接调用 Java 相关的 API，因为这可能会导致不稳定的行为或崩溃。
  • 如果你在 Java.perform 内部定义了异步操作（如网络请求），请确保这些操作完成之前不要让 Java.perform 结束，否则可能导致操作提前终止或出现异常情况。

总之，Java.perform 是在 Android 应用中进行 Java 层面 hook 和操纵的关键工具，确保了操作的安全性和正确性。

8、hook-重载-通过绑定签名来确定hook的函数

base64

import frida
import sys
rdev = frida.get_remote_device()
session = rdev.attach("识货")
scr = """
Java.perform(function () {
    var Base64 = Java.use("android.util.Base64");

    Base64.encodeToString.overload('[B', 'int').implementation = function (bArr,val) {
        var res = this.encodeToString(bArr,val);
        console.log("加密了-->",res);
        return res;
    }
});
"""
script = session.create_script(scr)
def on_message(message, data):
    print(message, data)
script.on("message", on_message)
script.load()
sys.stdin.read()

# 通过查看输出，那请求的数据搜索，发现hook到了

参数说明

  • '[B：这是一个 Java 类型描述符，表示字节数组（byte[]）。在 Java 中，[ 表示数组，B 表示基本数据类型中的字节（byte）。因此，'[B 意味着第一个参数是一个字节数组。
  • 'int：这是 Java 的基本数据类型之一，表示整数（int）。它指定了第二个参数是整数类型的值。

方法签名

所以，Base64.encodeToString.overload('[B', 'int') 表示的是对 android.util.Base64 类中的 encodeToString 方法进行 Hook，该方法接受两个参数：一个字节数组 (byte[]) 和一个整数 (int)。

根据 Android 官方文档，android.util.Base64.encodeToString 方法确实有一个重载版本，其签名如下：

public static String encodeToString(byte[] input, int flags)
  • input：要编码的字节数组。
  • flags：用于指定编码选项的标志位，例如是否应该添加换行符等。

hook说明

这段代码做了以下几件事：

  1. 选择特定重载：通过 .overload('[B', 'int') 来明确指出我们要 Hook 的是接受字节数组和整数作为参数的那个 encodeToString 方法。
  2. 替换实现：使用 .implementation = function (bArr, val) 来定义一个新的实现。在这个新实现中，首先调用原始的 encodeToString 方法来获取结果。
  3. 日志记录：将编码后的字符串打印到控制台。
  4. 返回结果：最后返回原始方法的结果，以确保应用程序的行为不会因为 Hook 而改变。

14、onEnter和onLeave

onEnter 和 onLeave 是 Frida 中用于函数拦截（或称 Hook）的两个重要回调函数，它们分别在目标函数调用开始和结束时触发。通过这两个回调，开发者可以在不修改原始代码的情况下，动态地获取函数的输入参数、输出结果以及执行过程中的状态信息。下面详细解释它们的作用：

onEnter

  • 触发时机：当目标函数即将被执行时，即在进入函数体之前。
  • 主要用途
  • 查看和修改入参：可以读取传递给函数的所有参数，并根据需要对其进行修改。这对于理解函数的行为、调试问题或实现特定逻辑非常有用。
  • 设置上下文：可以通过 this 关键字保存某些值到回调对象中，以便在 onLeave 回调中使用。例如，保存指针地址或其他临时数据。
  • 记录日志：打印出参数值以进行监控或日志记录，帮助分析函数调用的情况

示例：

Interceptor.attach(addr_func, {
    onEnter: function (args) {
        console.log("Function called with args:", args);
        // 可选：修改参数
        // args[0] = ...;
        this.savedArg = args[0]; // 保存参数供后续使用
    },
    ...
});

onLeave

  • 触发时机：当目标函数执行完毕并准备返回时，即在函数体结束后但还未真正返回给调用者之前。

  • 主要用途：

  • 查看和修改返回值：可以读取函数的返回值，并根据需要对其进行修改。这允许你在不改变源码的情况下调整函数的实际输出。

  • 访问保存的数据：如果在 onEnter 中保存了任何数据（如通过 this），可以在 onLeave 中访问这些数据，从而实现跨阶段的数据共享。

示例：

javascript Interceptor.attach(addr_func, { ... onLeave: function (retval) { console.log("Function returned with value:", retval); // 可选：修改返回值 // retval.replace(...); console.log("Saved argument from onEnter:", this.savedArg); } });

15、查看传入参数值处理后的结果

Java.perform(function () {
    var addr_func = Module.findExportByName("libkeyinfo.so", "getByteHash");
    Interceptor.attach(addr_func, {
        onEnter: function (args) {
            console.log("--------------------------执行函数--------------------------");
            console.log("参数2（指针）：", args[2]);
            this.x1 = args[2]; // 假设 args[2] 是一个指向 C 字符串的指针
        },
        onLeave: function (retValue) {
            // 访问保存的数据：如果在 onEnter 中保存了任何数据（如通过 this），可以在 onLeave 中访问这些数据，从而实现跨阶段的数据共享。
            try {
                if (this.x1 !== null && this.x1.toInt32() !== 0) {
                    var str = Memory.readCString(this.x1);
                    console.log("参数2对应的字符串:", str);
                } else {
                    console.log("参数2为空或无效指针");
                }
            } catch (e) {
                console.error("Error reading memory at address:", this.x1, e);
            }

            try {
                console.log("返回值:", retValue.readUtf8String());
            } catch (e) {
                console.error("Error reading return value as string:", e);
            }
        }
    });
});

Memory.readCString

在 Frida 中使用 Memory.readCString 方法时，它用于从指定的内存地址读取以 NULL 结尾（C 字符串）的数据，并将其转换为 JavaScript 字符串。具体来说，Memory.readCString(this.x1) 会尝试从 this.x1 所指向的内存地址开始读取字符，直到遇到第一个空字符 \0 为止，然后将这些字符组成的字符串返回。

理解 Memory.readCString(this.x1)

  • this.x1: 在你的代码中，this.x1 是你在 onEnter 回调函数中保存的一个参数（即 args[2]），这意味着它是传递给被 hook 函数 (getByteHash) 的第三个参数。这个参数应该是一个指向 C 字符串（以 \0 结尾的字符数组）的指针。
  • Memory.readCString: 这个方法会从 this.x1 指向的地址开始读取数据，直到遇到终止符 \0。因此，如果你知道 args[2] 确实是指向一个有效的 C 字符串，那么 Memory.readCString(this.x1) 就可以正确地读取出该字符串的内容并打印出来。

由于一个App中可能多处调用当前key、iv的位置，那么就无法确定当前esNav加密时候用的是哪个key和哪个iv、那么就需要再hook esNav开始和结束的时候分别添加开始和结束，那么在这个开始和结束中间所调用的key和iv，就是当前加密生成所需要的key和iv
